# ととのい黄金比

「サウナ〇分 + 水風呂〇分 + 外気浴〇分」の内容と、その日の「ととのい度」や体調を記録し、
**自分だけの黄金比(最もととのう時間配分)** をデータから見つけて提案する Web アプリです。

## 特化型AIとしてのポイント

汎用の対話AIは、あなたの体や、使う施設の水風呂の温度を知りません。このアプリは、
自分の記録そのものを学習データにして次の2段階で提案します。

1. **黄金比(集計)**: ととのい度4以上のセッションの平均時間配分を出します。水風呂14℃以下かどうか、施設ごと、でも分けます。
2. **予測モデル(機械学習)**: 時間配分と、睡眠・疲労・食事・温度から「ととのい度」を予測する回帰モデルと、「4以上になる確率」の分類モデルを学習します。今日のコンディションを固定して時間配分を総当たりし、予測スコアが最大の配分を提案します。

予測の信頼度は、交差検証で「平均点を答えるだけの基準」と比較して必ず画面に出します。
記録が少ないうちは(20件未満)モデルを使わず、集計の黄金比だけを使います。

## 機能

| 画面 | 内容 |
|---|---|
| 記録 | セットごとの時間入力、ストップウォッチ(押した区間の時間が自動で入る)、施設・室温・水風呂温度、睡眠・疲労度・食事、ととのい度(5段階)、メモ |
| 記録一覧 | 全件の一覧。施設名・メモ・日付・ととのい度で絞り込み、編集・削除 |
| 黄金比 | 全体 / 水風呂14℃以下と超 / 施設別 / **睡眠・疲れ・食事の条件別**の黄金比とベスト記録。記録が少ない条件は「参考程度」と表示し、足りない条件を案内 |
| 予測 | 今日のコンディションから最適な時間配分を提案。サウナ時間ごとの予測の変化、候補一覧、決めた配分の評価。**飲酒・体調不良・医師の制限があるときは予測を出さず注意を表示**。過去の予測と実際の結果を並べる**答え合わせ** |
| 振り返り | ととのい度の推移、月別回数、セット別平均時間、カレンダー |
| 医科学 | PubMed を検索し、質問に近い論文の書誌情報・抄録抜粋・PMIDリンクを提示する出典付きRAG |
| ログイン・登録 | 別ページ(`login.html` / `register.html`)。登録時に `privacy.html`(データの扱い)への同意が必要。同意した版と日時を保存し、説明文の版を上げると再同意を求める |
| データ・設定 | CSVの書き出し / 取り込み(先に確認、重複は取り込まない)、パスワード変更、記録の全削除、アカウント削除 |

記録フォームは、入力途中の内容とタイマーを、この端末のブラウザに保存します(閉じても続きから)。施設名は、「いまの場所から選ぶ」で、現在地に近い施設を選べます(自分の記録にある施設を先に、そのあと OpenStreetMap で探した近くのサウナ・銭湯・温泉を出します)。位置は約110mに丸めて保存し、CSVには含めません。「開いたときに自動で選ぶ」をオンにすると、自分の記録の施設が150m以内にあるときだけ、自動で選びます(この場合、外部へは問い合わせません)。位置情報だけを削除することもできます。施設名は、よく行く順のボタン(上位5件)で選べ、前回の温度も自動で入ります(入力済みの欄は上書きしません)。ほかに、週の目標の表示、安静時心拍の任意入力(いまは記録だけで予測には使わない)、ホーム画面への追加(`manifest.webmanifest`)に対応しています。

## 自前の論文検索モデルと評価

医科学タブの検索は、PubMed に任せる方式(`/api/research`)に加えて、**自分たちで作った検索モデル**(`/api/research/local`)を用意しています。
あらかじめ保存した論文の抄録を TF-IDF で索引化し、日本語の質問を英語の検索語に変換して、近さの順に並べます(`backend/app/retrieval.py`)。

```bash
npm run corpus   # PubMed から抄録を集めて保存(要ネット接続・数分)。backend/data/corpus.jsonl ができる
npm run eval     # 正解データを使って、検索方式どうしを数字で比べる
```

1. `npm run corpus` で論文を保存します。抄録の著作権は出版社にあるため、保存したファイルは Git に入れません。各自のパソコンで作ります。
2. `backend/data/eval_queries.json` の `relevant_pmids` に、質問ごとの正解の論文(PMID)を入れます。チームで手分けして、論文を読んで付けてください。
3. `npm run eval` で、キーワード一致(基準)と TF-IDF を Hit@1・Recall@5・MRR で比較します。正解ありの質問が 20 件未満のときは、差が偶然の可能性があると表示されます。

保存した論文を増やしたいときは、`backend/app/build_corpus.py` の `SEED_QUERIES` に PubMed の検索式を足します。
日本語の質問を英語に直す辞書は、`backend/app/retrieval.py` の `EXTRA_EXPANSIONS` に足せます。

## 起動方法

Node.js 18 以上と、Python 3.10 以上が必要です。予測モデルが Python(scikit-learn)で動くためです。

```bash
npm run setup   # 初回だけ。Python の専用環境(.venv)を作ってライブラリを入れる
npm run dev     # 起動
```

表示されたURL(通常は http://127.0.0.1:8000)をブラウザで開きます。8000番が使用中なら、空いている次のポートが自動で選ばれます。
画面は同じサーバーから配信されるので、フロントエンドのビルドは不要です。

<details>
<summary>npm を使わずに起動する場合</summary>

```bash
python -m venv .venv
source .venv/bin/activate        # Windows は .venv\Scripts\activate
pip install -r requirements.txt
cd backend
uvicorn app.main:app --reload
```

</details>

専用環境(.venv)を使うのは、他のプロジェクトで入れた numpy や pandas とバージョンが衝突して起動できなくなるのを防ぐためです。
ただしグラフ(Chart.js)とフォントは CDN から読み込むため、画面の表示にはインターネット接続が必要です。

記録は `backend/sauna.db`(SQLite)に保存されます。別の場所を使うときは環境変数 `SAUNA_DB` にパスを指定します。
HTTPSで公開する場合は、環境変数 `SAUNA_COOKIE_SECURE=true` を設定してください。

はじめて試すときは、ページ下の「サンプルを追加」を押すと架空の記録が60件入り、全機能を確認できます。
サンプルは自分の記録と区別され、いつでも一括削除できます。

## CSVの形式

1セット1行です。同じ `record_no` の行は、同じ記録のセットとして束ねます。UTF-8(書き出しはBOM付き)。
列: `record_no, visited_on, facility, sauna_temp, water_temp, sleep_hours, resting_hr, fatigue, ate_before, score, note, set_no, sauna_min, water_min, rest_min`
(`resting_hr` は古い書き出しに無くても取り込めます。)取り込みは、保存前に `POST /api/import/sessions`(commit=false)で内容を確認でき、形式が正しくない記録は飛ばし、打ち間違いの疑いは一覧にして知らせます。書き出しでは、`=` `+` `-` `@` で始まる文字の前に `'` を付け、表計算ソフトで式として実行されないようにしています。

## バックアップ

```bash
npm run backup   # backend/backups/sauna-日時.db に、実行中でも安全にコピー(14世代まで残す)
```

バックアップには全員の記録とパスワードのハッシュが入ります。共有・公開しないでください(Git対象外)。定期実行したいときは、cron などから `npm run backup` を呼びます。

## 入力ミスの警告

範囲外の値は 422 で拒否します(未来の日付も)。範囲内でも打ち間違いが疑われる値(サウナ室60〜110℃・水風呂4〜25℃・睡眠2〜14時間の外、1セットのサウナ20分超・水風呂5分超・休憩60分超、サウナ0分、1年以上前の日付)は、POST/PUT が 409 で警告の一覧を返して止めます。確認のうえ `?confirmed=true` を付けると保存できます。判定は `backend/app/checks.py` にまとめています。

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET / POST | `/api/sessions` | 記録の一覧(新しい順)/ 追加 |
| PUT / DELETE | `/api/sessions/{id}` | 記録の編集(セットごと置き換え)/ 削除 |
| GET | `/api/facilities/nearby` | 現在地(lat, lng)に近い施設。`known`(自分の記録)と `suggested`(OpenStreetMap)。`external=false` で外部への問い合わせなし |
| GET | `/api/export/sessions.csv` | 自分の記録をCSVで取得(サンプルは既定で除く) |
| POST | `/api/import/sessions` | CSVの取り込み(`commit=true` で保存。既定は確認のみ) |
| GET | `/api/predictions/review` | 過去の予測と、同じ日の実際の記録の比較 |
| POST | `/api/account/consent` / `password` / `clear-locations` / `delete-data` / `delete` | 再同意 / パスワード変更 / 位置情報だけ削除 / 記録の全削除 / アカウント削除(削除系はパスワード必須) |
| GET | `/api/analysis/golden` | 黄金比(全体・水風呂温度別・施設別) |
| GET | `/api/analysis/dashboard` | グラフ・カレンダー用の集計 |
| POST | `/api/predict` | 今日のコンディションから最適な配分を予測 |
| POST | `/api/research` | PubMedを使った医学論文RAG（`{"question": "..."}`） |
| POST | `/api/research/local` | 保存済み論文を自前のTF-IDFで検索(通信不要。先に `npm run corpus`) |
| POST | `/api/auth/register` | 新規登録（ログインCookieを設定） |
| POST | `/api/auth/login` / `/api/auth/logout` | ログイン / ログアウト |
| GET | `/api/auth/me` | ログイン中のユーザー情報 |
| POST / DELETE | `/api/sample` | サンプルデータの追加 / 削除 |

`include_sample=false` を付けると、サンプルを除いた記録だけで分析・予測します。

## 公開前に決めること(チームで)

- `frontend/privacy.html` に、**連絡先(問い合わせ先)**を書いてください。いまは「開発チームへ連絡してください」とだけ書いてあります。
- 大学などの研究としてデータを使う場合は、**倫理審査が必要か**を指導教員に確認してください。確認が済むまでは、同意文の「開発・改善に使う」の範囲を広げないでください。
- 説明文を変えたら、`backend/app/auth.py` の `CONSENT_VERSION` を更新します(利用者に再同意を求めます)。
- 位置情報の取得(ブラウザの機能)は、`https` または `localhost` のページでだけ動きます。公開するときは HTTPS が必要です。
- 施設の検索は、無料の公開サービス(Overpass API)を使います。たくさんの人が使う段階になったら、利用ルールを確認するか、自前のサーバーを立てて `SAUNA_OVERPASS_URL` で切り替えてください。止めたいときは `SAUNA_DISABLE_EXTERNAL_PLACES=1`。
- HTTPS で公開するときは、環境変数 `SAUNA_COOKIE_SECURE=1` を付けます。

## 既知の制限

- ととのい度は主観評価で、1人の記録は数十件程度です。モデルの予測はあくまで目安で、医学的な安全性を保証するものではありません(高血圧など持病がある場合は医師の指示を優先してください)。
- 医科学コンシェルジュはPubMedの論文を検索して出典を示す機能であり、診断・治療・個別の安全判断を行いません。通信できない環境では利用できません。
- 認証導入前の既存データには所有者情報がありません。アップデート後、最初に新規登録したアカウントへ一度だけ引き継がれます。共有環境を更新する場合は、更新前にDBをバックアップしてください。
- サンプルデータは「サウナ約9.5分・水風呂約1.3分・休憩約11分がととのいやすい」と仮定して作った架空のものです。サンプルで出る結果は、実際のととのい方を表しません。
